# korean-report-style

한국어 보고서와 논문 원고를 보고서와 논문 문체로 고친다. writing-fixer가 단어와 문장의 결을 다룬다면, 이 스킬은 문서의 구조(제목, 절, 문단, 표), 보고서 어휘, 시제와 주어, 문법, 사실 처리를 다룬다. 두 스킬의 기준을 함께 적용한다.

두 스킬이 어긋나면 다음 순서로 정한다.

1. 구조(제목, 절, 문단과 표 사이의 전환), 보고서 어휘(3절), 장르 규칙(5절)은 이 스킬을 따른다.
2. 그 밖의 단어와 문장 교정(구어체, 번역체, 예스런 말, 따옴표, 쉼표)은 writing-fixer를 따른다.
3. writing-fixer의 "새 문장을 쓰지 않는다" 규칙은 새 **사실**을 쓰지 않는다는 뜻으로 적용한다. 원문의 사실을 표로 옮기며 붙이는 열 이름, 표 제목(캡션), 문장 주어("이 과제는"), [확인 필요] 자리표시는 새 사실이 아니므로 쓸 수 있다. 안내문("다음과 같다"), 요약문, 다짐은 여전히 쓰지 않는다.

korean-naturalizer는 블로그와 에세이까지 다루므로 입말 쪽으로 기운 규칙이 있다. 보고서와 논문에는 다음을 적용하지 않는다: 표준 한자어 동사를 고유어로 바꾸기(제공한다 → 내놓는다), 구어체 삽입("쉽게 말해", "솔직히"), 입말 종결("~인 셈이다", "~거든").

## 작업 원칙

- **원뜻 보존**: 수치, 고유명사, 인과 관계, 주어와 목적어의 역할을 바꾸지 않는다. 바꾸는 것은 구조와 표현이다.
- **삭제 우선**: 새 표현을 넣기 전에 지워도 되는 것(안내문, 빈 수식어, 다짐, 중복 서술, 불필요한 영어 병기)부터 지운다.
- **범위 유지**: 사용자가 지정한 파일과 절 밖으로 나가지 않는다.
- **사실은 지어내지 않는다**: 모르는 것은 [확인 필요]로 남긴다(7절).
- **근거를 남긴다**: 작업을 마치면 무엇을 어떤 규칙(절 번호)으로 고쳤는지 짧게 보고한다.
- **작성과 검토를 나눈다**: 교정한 패스에서 스스로 승인하지 않는다. 교정이 끝나면 9절의 검토 패스를 세 번 실행한다.

## 목표 문체

| 요소 | 쓴다 | 쓰지 않는다 |
|------|------|-------------|
| 제목 | 명사형 ("시제품 제작", "문제점 및 대응 방안") | 문장형, 의문형, 콜론형, 괄호 덧붙임 |
| 본문 | 주어와 서술어를 갖춘 하다체 문단 | "라벨: 문장" 불릿 나열, 명사로 끝난 문장 |
| 구조화된 사실 | 표 (일정, 지표, 예산, 사양, 기관 분담) | 같은 사실을 문단과 표에 중복 서술 |
| 표 칸 | 명사형 ("진행 중", "장비 입고 후 측정") | 완결 문장 |
| 불릿 | 실제로 병렬인 목록 (업무 목록, 번호 매긴 역할) | 서술을 잘게 쪼갠 개조식 |

종결 형식은 원고와 발주처 양식을 따른다. 기본은 하다체이다. 양식이 합쇼체(~합니다)나 명사형 개조식(~함, ~임)을 요구하면 그 형식으로 통일하고, 한 문서 안에서 섞지 않는다. 원고와 요청 어디에서도 판단할 수 없을 때만 한 번 묻는다.

## 1. 제목과 절

AI가 만든 문서는 제목에서 먼저 드러난다.

| 패턴 | 예 | 고친 예 |
|------|----|---------|
| 문장형, 의문형 | "왜 이 방식인가", "장비를 어떻게 바꿨나", "~를 알아보자" | "방식 선정 배경", "장비 개선" |
| 제목과 부제를 콜론으로 이음 | "적용 장비: A사 가속 보드" | "적용 장비" (제품명은 본문 첫 문장으로) |
| 범위를 괄호로 덧붙임 | "과업별 수행 구분 (1차년도)", "시제품 제작 (3식)", "사전 검증 (시뮬레이션)" | "과업별 수행 구분" (범위는 표 머리글이나 본문으로) |
| 약어 병기 | "역할과 책임 (R&R)" | "수행 체계 및 역할" |
| 캐주얼, 과장 | "~ 맛보기", "~ 한눈에", "핵심 정리", "들어가며", "마치며" | 주제명만 남기거나 절 삭제 |
| "A와 B" 병렬 | "문제점과 대응", "인력과 사업비" | "문제점 및 대응 방안", "인력 및 사업비 집행 현황" |

- 두 항목을 묶는 제목은 "및"을 쓴다.
- 절 번호는 양식이 붙이므로 제목에 번호를 직접 쓰지 않는다. "요약"은 번호 없는 절로 둔다(Quarto: `## 요약 {.unnumbered}`).
- 표지 부제도 콜론 문장으로 쓰지 않는다. "1차년도 중간보고: 참여기관 2 …"는 분류 라벨(kicker) "1차년도 중간보고"와 부제 "세부과제 「…」 참여기관 2 (주)…"로 나눈다.
- 같은 수준의 제목은 같은 형태로 맞춘다. 한 절은 "~ 개발", 옆 절은 "~를 개발함"처럼 섞지 않는다.
- 모든 절을 "도입 한 줄, 본론, 마무리 한 줄"의 같은 틀로 쓰지 않는다. 절의 길이와 구성은 내용이 정한다.

## 2. 본문 문단

### 라벨 불릿을 문단으로

"- 현황: 설치 완료 / - 용도: 시범 운영 / - 분담: …"처럼 라벨에 콜론을 붙인 불릿 나열은 AI 개조식의 전형이다. 같은 사실을 하다체 문단 한두 개로 잇는다.

- before: `- 현황: 설치 완료` `- 용도: 현장 적용성 확인을 위한 시범 운영`
- after: `시험 장비는 설치를 완료했으며, 현장 적용성을 확인하기 위해 ○○ 시설에서 시범 운영했다.`

명사로 끝난 문장은 서술어로 끝맺는다. "성공률 95% 이상" → "성공률은 95% 이상이다".

### 주어와 행위자

- 문장마다 누가 한 일인지 분명히 쓴다. 기관이 여럿인 과제는 주관기관, 참여기관, 용역기관의 몫을 문장마다 구분한다. 역할이 흐려지면 평가에서 문제가 된다.
- 주어가 빠져 행위자가 모호한 문장("이 밖에 여러 모델을 구동했다")은 주어를 넣거나 서술을 바꾼다("제조사는 이 밖에 여러 모델의 구동 결과도 공개했다").
- 한 문단 안에서 주어가 바뀌면 바뀐 문장에 주어를 다시 쓴다.
- 기관이나 사람이 한 일은 능동으로 쓴다("B사가 시제품을 제작한다").
- 제품과 장비의 구성, 제조는 행위자가 드러나지 않으므로 피동이 자연스럽다("코어 8개로 구성되며 7 nm 공정으로 제조된다").

### 시제와 상

| 대상 | 형태 | 예 |
|------|------|----|
| 완료한 일 | 과거형 | "데이터 수집 모듈을 구현했다." |
| 진행 중인 일 | "~하고 있다", "진행 중이다" | "평가 기준을 재검토하고 있다." |
| 계획 | "~할 계획이다", "~할 예정이다" | "현장에서 반복 측정할 계획이다." |
| 상태와 사양 | 현재형 | "측정 주기는 1초이다." |

- 시점이 확인되지 않은 일에 현재형을 써서 완료와 예정을 흐리지 않는다. 확인이 필요하면 [확인 필요]를 붙인다.
- 기준 시점은 연도까지 쓴다("2026년 3월 말 기준").

### 문장 구조

- 앞뒤가 대비되면 "-으나", "-지만"으로 잇는다. "입고 예정일은 5월이었으며 현재 11월 입고가 예정되어 있다"는 대비이므로 "입고 예정일은 5월이었으나 현재 11월 입고가 예정되어 있다"로 쓴다.
- "~하고, ~하며, ~한다"로 셋 이상 잇지 않고 문장을 나눈다. 한 문장에 절이 셋을 넘으면 나눈다.
- 관계절을 겹겹이 쌓지 않는다. "기존에 제안된 방법을 개선한 것으로서 성능을 높이는 데 기여하는 방법" → "기존 방법을 개선해 처리 시간을 단축한 방법".
- 명사구를 "의"로 잇는 나열을 풀어 쓴다. "처리 효율성 향상의 달성을 위한 방법론의 적용" → "처리 시간을 줄이기 위해 이 방법을 적용했다".
- 같은 접속어("또한", "아울러", "이에")를 잇따라 쓰지 않는다. 절반은 접속어 없이 잇는다.

### 평가와 강조

- 평가어는 근거가 있을 때만 쓴다. "가장 큰 현안", "성공적으로", "매우 우수한", "획기적인", "강력한", "최고 수준의"는 사실 서술로 바꾼다("주요 현안은 장비 입고 지연이다").
- 나열을 셋으로 맞추지 않는다. 원문에 근거가 있는 항목만 쓴다.
- 같은 뜻을 두 번 쓰는 병렬("효율적일 뿐만 아니라 생산적이기도 하다")은 한쪽만 남긴다.
- "~함으로써", "~를 통해"로 인과를 얼버무리지 않는다. 실제 메커니즘을 쓰거나 지운다.
- 출처 없는 "업계에서는", "연구에 따르면"은 출처를 밝히거나 지운다.
- 약속, 다짐, 자평("최선을 다할 것이다", "견고한 체계를 갖추었다")은 쓰지 않는다.
- 불리한 사실을 에둘러 쓰지 않는다. "일부 차질이 있었다" → "입고가 2개월 지연되었다". "목표에 다소 미치지 못했다" → "목표 90%에 대해 82%를 달성했다".
- 굵은 글씨는 문단마다 쓰지 않는다. 한 문단에 둘을 넘기지 않는다.
- 영어 병기는 전문 용어가 처음 나올 때 한 번만 한다. 뻔한 병기("성능(Performance)")는 지운다.

## 3. 보고서 및 논문 어휘

입말 어휘를 보고서와 논문에서 쓰는 표준 어휘로 바꾼다. 예스러운 말로 넘어가지 않는다(writing-fixer E절).

| 입말 | 보고서, 논문 |
|------|-------------|
| 앞으로 | 향후 |
| 쓴다 (도구, 장비, 모델, 함수, 자료형, 방법, 값을) | 사용한다 ("그대로 쓴다" → "그대로 사용한다", "`floor`를 쓴다" → "`floor`를 사용한다") |
| 쓴다 (기술을 설비나 현장에) | 적용한다 |
| 고른다 | 선택한다 |
| 정한다 | 결정한다, 설정한다 |
| 옮긴다 (모델을 기기로) | 이식한다 |
| 따로 운용한다 | 분리하여 운용한다, 별도로 운용한다 |
| 바꾼다 | 변경한다 |
| 늘어난다, 줄어든다 | 증가한다, 감소한다 |
| 만든다 (시제품, 체계를) | 제작한다, 구축한다 |
| 시작한다 (과업을) | 착수한다 |
| 끝낸다 | 완료한다 |
| 늦어진다 | 지연된다 |
| 알아본다 | 조사한다, 검토한다 |
| 맞춘다 (결과를 계획에) | 반영한다 |
| 커스터마이징한다 | 개조한다 |
| 테스트 (한 문서 안에서 "시험"과 혼용) | 한 용어로 통일 |
| 남긴다 (값, 기록, 표시를) | 저장한다, 기록한다, 둔다, 유지한다 |
| 엉뚱한 (값, 결과) | 전혀 다른, 잘못된 |
| ~에서 이어진다, ~으로 이어진다 (절과 자료를 잇는 연결 문장) | ~의 다음 내용이다, ~를 바탕으로 한다, 또는 삭제 |
| 따라간다, 따라가기 (코드, 출력, 흐름, 표를) | 출력을 구한다, 실행 과정을 표로 적는다, 순서대로 계산한다 |
| 모았다, 옮겼다, 정리했다, 넣었다, 담았다 (문서를 만든 과정을 과거형으로 서술) | 정리한다, 담는다, 다룬다, ~에 있다 (문서 내용은 현재형으로 설명한다) |

- "쓴다"는 글이나 답안, 코드를 적는 뜻(글을 쓴다, 답을 쓴다)에만 남긴다. 도구, 함수, 방법, 값을 이용한다는 뜻이면 "사용한다"로 바꾼다. 프로젝트 규칙이 예전에 "사용하다 → 쓰다"를 요구했더라도 이 규칙을 우선한다.
- 이야기하듯 쓰지 않는다. 문서를 만든 사람이 한 일을 과거형으로 서술하지 않고("~로 옮겼다", "~를 모았다"), 문서의 내용을 현재형으로 설명한다("~에서 정리한다"). 실제 과거 사실(기출이 물은 내용, 역사)만 과거형으로 쓴다.
- 한 문서 안에서 같은 대상은 같은 용어로 부른다(시험과 테스트, 현황과 현재 상태, 개조와 커스터마이징을 섞지 않는다).
- 표준 한자어 동사(수행한다, 구축한다, 적용한다, 제공한다)는 그대로 둔다. 고유어로 되돌리지 않는다.
- 번역체 틀은 고친다: "~를 갖는다" → "~가 있다", "~를 필요로 한다" → "~가 필요하다", "~에 위치한다" → "~에 있다", "~하기 위해서는" → "~하려면", "~에도 불구하고" → "~지만".
- 무생물 주어의 피동 남용을 고친다: "요구된다" → "필요하다", "기대된다" → "기대할 수 있다". 이중 피동("되어진다", "보여진다")은 틀린 문법이다.

## 4. 문법

AI가 자주 틀리는 문법을 교정할 때마다 확인한다.

| 항목 | 틀림 | 맞음 |
|------|------|------|
| 서술격 조사 (문어체) | 이것은 결과다 | 이것은 결과이다 |
| 조사 받침 | 서버을, 값를, 결과은 | 서버를, 값을, 결과는 |
| "와/과" 반복 | 속도와 정확도와 | 속도, 정확도와 / 속도와 정확도 |
| 무정물 "에게" | 서버에게 전송한다, 시스템에게 알린다 | 서버에 전송한다, 시스템에 알린다 |
| 동사 종결 | 이 방법이 맞다, 값이 들어가다 | 이 방법이 맞는다, 값이 들어간다 |
| 형용사 종결 | 빠르는다, 있는다 | 빠르다, 있다 |
| 기본형 종결 | 결과를 반환하다. | 결과를 반환한다. |
| 띄어쓰기 | 할수있다, 해야한다, 수행할수 없다 | 할 수 있다, 해야 한다, 수행할 수 없다 |
| 맞춤법 | 됬다, 몇일, 금새 | 됐다, 며칠, 금세 |
| 긴 부정 (문어체 기준, 문법 오류는 아님) | 안 한다, 못 맞춘다 | 하지 않는다, 맞추지 못한다 |

## 5. 장르별 규칙

### 보고서

- 정부 R&D 중간보고서와 결과보고서를 새로 쓰거나 전체를 고칠 때, 양식이 없으면 이 순서를 쓴다. 해당 없는 절은 뺀다. 원고의 일부만 고칠 때는 절 순서를 바꾸지 않고 각 절 안에서 고친다.
  1. 요약 (번호 없음. 문단 하나, 현황 표 하나, 현안 문장 하나)
  2. 과제 개요 (과제 정보 표, 서비스 개요, 적용 기술과 장비)
  3. 수행 체계 및 역할 (기관 역할, 기관별 분담, 과업별 수행 구분, 담당 성과지표)
  4. 추진 일정 및 진도
  5. 추진 실적 (과업별 하위 절)
  6. 인력 및 사업비 집행 현황
  7. 문제점 및 대응 방안 (문제점, 영향, 대응, 일정 표)
  8. 향후 추진 계획
- 과제를 가리킬 때는 "이 과제"를 쓴다. 발주처 양식이 "본 과제"를 쓰면 양식을 따른다.

### 논문

- 절 구성은 서론, 관련 연구, 방법, 실험 및 결과, 고찰, 결론을 기본으로 하고 학회 양식을 우선한다.
- "본 연구", "본 논문"은 논문의 관례 표현이므로 허용한다(writing-fixer의 "본 문서 → 이 문서" 규칙보다 우선).
- 1인칭 "우리는", "나는"을 쓰지 않는다. "본 연구에서는 ~를 제안한다"처럼 쓴다.
- 주장의 강도는 근거에 맞춘다. 실험으로 보인 것은 단정하고, 추론은 "~로 해석할 수 있다"처럼 근거를 밝혀 쓴다. 근거 없는 "~로 보인다"는 쓰지 않는다.
- 그림과 표는 모두 캡션을 달고 본문에서 번호로 참조한다(Quarto: `@tbl-...`, `@fig-...`).

## 6. 표와 캡션

- "다음과 같다", "아래 표는", "다음 표와 같이" 같은 표 안내문을 쓰지 않는다. 표는 스스로 보인다.
- 안내문에 들어 있던 조건은 표 머리글로 옮긴다. "1차년도 과업별 수행 구분은 다음과 같다" → 머리글 `과업 (1차년도)`. "배치 8 기준 결과" → 머리글 `모델 (배치 8)`.
- 캡션은 모든 표에 달거나 모두 달지 않는다. LaTeX는 캡션 없는 표까지 번호를 세므로, 일부 표에만 캡션을 달면 첫 캡션이 "표 9"처럼 나온다.
- 출처는 해당 문장 끝 괄호에 넣는다: `…모델 개발사가 공개한 벤치마크 값이며(개발사 기술 보고서 표 3) 자체 측정값이 아니다.` 긴 URL이 들어간 문장은 양쪽 정렬 때문에 자간이 벌어지므로 URL을 줄이거나 저장소 이름으로 쓴다.
- 표 칸 안의 나열은 쉼표로 잇되, 여러 층위가 섞이면 "와/과", "및"으로 묶어 뜻이 흐려지지 않게 한다("온도와 습도와 진동"이 아니라 "온도, 습도, 진동").

## 7. 사실 처리

- 모르는 사실, 수치, 날짜는 `[확인 필요: 필요한 내용]`으로 남긴다. 추정치를 사실처럼 쓰지 않는다.
- 자리표시 괄호 안에는 채워야 할 항목을 구체적으로 적는다(`[확인 필요: 시험 장소, 시행 횟수, 판정 기준]`). 항목을 특정할 수 없으면 무엇을 적을지 적는다(`[확인 필요: 사용자 의견 요약]`).
- 자리표시도 문장 안에서 문법이 맞게 둔다. "사용자 의견은 [확인 필요]." 대신 "시범 운영에서 수렴한 사용자 의견은 [확인 필요: 요약]이다."
- 측정 주체를 밝힌다. 개발사 공식 벤치마크, 제조사 발표치, 자체 시뮬레이션, 자체 실측을 구분한다("모델 개발사가 공개한 벤치마크 값이며 자체 측정값이 아니다").
- 시험 결과에는 조건(장소, 횟수, 판정 기준, 배치 크기, 양자화 조건)을 붙이거나 [확인 필요]로 남긴다. 시험 결과를 현장 성과지표 달성으로 쓰지 않는다("시험 95% (현장 측정 전)").
- 사용자가 준 수치는 받은 값과 조건 그대로 쓴다. 다른 값으로 환산하거나 해석이 필요하면 사용자에게 먼저 묻는다.
- 본문의 주장이 같은 문서의 표나 수치와 어긋나면(예: 오류율이 더 높은데 "제안 방법이 우수하다") 수치를 그대로 두고, 어긋난 주장은 옮기지 않는다. 그 자리에는 짧은 자리표시만 둔다(`[확인 필요: 결론 근거]`). 모순을 설명하는 논평 문장을 문서에 새로 쓰지 않고, 모순 내용은 작업 결과를 보고할 때 사용자에게 알린다. 주장을 수치에 맞춰 반대로 고쳐 쓰는 것도 해석이므로 사용자에게 먼저 묻는다.
- 자리표시는 짧은 명사구로 쓴다. 분석이나 설명을 자리표시 안에 넣지 않는다.
- 계획서와 달라진 점(사양 변경, 비목 변경, 일정 지연)은 문제점 및 대응 방안 표에 문제점, 영향, 대응, 일정 열로 적는다. 문제점 칸에는 원인까지 함께 쓴다.

  before:

  > 가장 큰 문제는 센서가 늦게 온 것이다. 센서는 8월 입고 예정이었으며, 10월에 받았다. 그래서 데이터 수집이 늦어졌고, 모델도 다시 골랐고, 일정도 바꿨다. 앞으로 최선을 다할 것이다.

  after:

  | 문제점 | 영향 | 대응 | 일정 |
  |---|---|---|---|
  | 센서 입고 지연 (계획 8월, 실제 10월) | 데이터 수집 지연 | 모델 재선택, 일정 변경 | [확인 필요: 변경된 일정] |

  평가어("가장 큰"), 다짐("최선을 다할 것이다")은 옮기지 않는다. 원문에 없는 일정은 지어내지 않고 자리표시로 둔다.
- 외부 사양(장비, 모델, 행사 일정)은 공식 자료에서 확인하고 출처를 단다. 시제품과 양산판처럼 버전이 다른 수치를 섞지 않는다.
- 원본 계획서가 크면 `pdftotext -layout`으로 추출해 해당 기관 부분을 읽고, 인용한 쪽번호는 추출 텍스트의 쪽 표시로 다시 확인한다. 간트 차트처럼 텍스트로 추출되지 않는 표는 해당 쪽을 이미지로 렌더해 읽는다.

## 8. 표기

- 범위는 하이픈으로 쓴다: 3-5월, 2026. 4. 7.-9., 10-15 L.
- 가운뎃점(·)은 쉼표, "와/과", "및"으로 바꾼다.
- 숫자와 단위는 띄운다: 5 kg, 100 MB/s, 32 TOPS, 150 ms. 퍼센트(%)와 원화 단위(천원)는 붙인다.
- PDF 글꼴에 없는 문자를 쓰지 않는다. 원문자(①②)는 사라지므로 "참여기관 2"처럼 숫자로 쓴다.
- 문장부호: em dash(—)와 en dash(–)는 쓰지 않는다. 둥근 따옴표는 곧은 따옴표로 바꾼다.

## 9. 작업 순서와 검토 패스

### 교정

1. 원고를 처음부터 끝까지 읽는다. grep으로 대신하지 않는다.
2. 제목과 절 구조를 고친다(1절, 5절).
3. 라벨 불릿과 명사 종결을 문단과 완결 문장으로 바꾸고, 주어, 시제, 문장 구조를 바로잡는다(2절).
4. 입말 어휘, 번역체, 혼용 용어를 정리한다(3절).
5. 문법을 확인한다(4절).
6. 표 안내문을 지우고 조건을 머리글로 옮기며, 캡션과 출처를 정리한다(6절).
7. writing-fixer 기준으로 단어와 문장을 다듬는다.

### 검토 패스 (기본 세 번)

교정이 끝나면 아래 세 검토 패스를 차례로 실행한다. 패스마다 원고를 처음부터 끝까지 다시 읽는다. 앞 패스에서 고친 문장도 다시 검토 대상이다. 문제를 찾으면 그 자리에서 고치고 다음 패스로 넘어간다. 사용자가 다른 횟수를 지정하지 않는 한 세 패스를 모두 실행하며, 하나라도 건너뛰지 않는다. 사용자가 횟수를 지정하면 그 횟수를 따른다.

1. **1차 검토 (구조)**: 제목이 명사형이고 같은 수준끼리 형태가 같은지, 라벨 불릿과 명사 종결 문장이 남았는지, 표 안내문과 요약문과 다짐이 새로 생기지 않았는지, 캡션이 모든 표에 있거나 모두 없는지, 제목에서 뺀 정보(범위, 수량, 조건)가 본문이나 표에 남아 있는지 확인한다.
2. **2차 검토 (문장과 문법)**: 문장마다 주어와 행위자, 시제, 대비 연결, 절 개수를 확인한다. 3절 어휘 표와 4절 문법 표, writing-fixer 카탈로그를 기준으로 입말, 번역체, 예스런 말, 조사, 띄어쓰기, 종결을 확인한다. 용어가 문서 전체에서 하나로 통일되었는지 본다.
3. **3차 검토 (사실과 결과물)**: `git diff`나 원문 대조로 수치, 기관명, 모델명, 날짜, [확인 필요] 표시가 원문 그대로인지 확인한다. 새 사실이나 해석이 들어가지 않았는지, 측정 주체와 조건이 밝혀졌는지 본다. 렌더하는 문서는 렌더한 뒤 PDF를 쪽 이미지로 확인한다(목차, 표지, 표 줄바꿈, 자간, 캡션 번호, 사라진 글리프). 용지는 `pdfinfo out.pdf | grep "Page size"`로 확인한다.

원고가 길거나(1,000자 이상) 공개 발행할 문서는 3차 검토를 교정하지 않은 별도 검토자(서브에이전트)에게 맡길 수 있다. 이때 이 스킬 파일과 원문, 수정본을 함께 준다.

### 커밋과 보고

- 자기가 고친 파일만 스테이징해 커밋한다. 다른 작업의 미커밋 변경(양식, 다른 문서)은 커밋에 넣지 않고, rebase가 필요하면 stash로 잠시 빼 둔다.
- 양식(글꼴, 한영 간격, 표지)이 바뀌면 쪽수와 줄바꿈이 달라진다. 렌더 결과가 달라졌으면 원고 수정 때문인지 양식 변경 때문인지 구분해 보고한다.
- 보고에는 검토 패스마다 찾아 고친 항목을 적는다. 찾은 것이 없는 패스도 "없음"으로 적는다.

## 자주 하는 실수

| 실수 | 바른 처리 |
|------|-----------|
| 제목의 괄호를 지우면서 "(1차년도)" 같은 정보를 버린다 | 표 머리글이나 본문 첫 문장으로 옮긴다 |
| 라벨 불릿을 문단으로 바꾸면서 "다음과 같다"를 새로 넣는다 | 넣지 않는다. 표 앞에 안내문 없이 표를 둔다 |
| 일부 표에만 캡션을 단다 | 모두 달거나 모두 뺀다 |
| 입말을 예스러운 말로 바꾼다 (앞으로 → 차후, 쓴다 → 활용한다) | 3절 표의 표준 어휘로 바꾼다 (향후, 사용한다) |
| korean-naturalizer 규칙대로 한자어를 고유어로 바꾼다 (제공한다 → 내놓는다) | 보고서에서는 표준 한자어 동사를 유지한다 |
| 대비 관계를 "-며"로 잇는다 | "-으나", "-지만"으로 잇는다 |
| 기관 활동을 피동으로 써서 행위자를 숨긴다 | 기관을 주어로 능동으로 쓴다 |
| 지연이나 미달을 "일부 차질"처럼 에둘러 쓴다 | 기간과 수치로 직접 쓴다 |
| 사용자가 준 수치를 해석해 다른 수치로 바꿔 쓴다 | 받은 값과 조건 그대로 쓰고, 해석이 필요하면 묻는다 |
| 시뮬레이션이나 공개 벤치마크를 자체 실측처럼 쓴다 | 측정 주체와 조건을 밝힌다 |
| 본문 주장과 표 수치의 모순을 문서 안 논평으로 설명한다 | 주장은 옮기지 않고 짧은 자리표시를 두며, 모순은 사용자에게 보고한다 |
| 제목만 고치고 본문 라벨 불릿을 남긴다 | 구조 전체를 한 번에 고친다 |
| 검토 패스를 한 번만 하고 끝낸다 | 구조, 문장과 문법, 사실과 결과물의 세 패스를 모두 실행한다 |
| 양식 변경으로 달라진 쪽수를 원고 수정 결과로 보고한다 | 원인을 구분해 보고한다 |

## 스킬 예시 작성 규칙

이 스킬 파일은 공개 저장소에 올라간다. 예시를 고치거나 추가할 때 실제 작업한 문서의 기관명, 과제명, 제품명, 인명, 수치, 일정을 넣지 않는다. A사, B사, ○○ 시설, 참여기관 2처럼 가상의 이름과 일반적인 수치로 바꿔 쓴다.
